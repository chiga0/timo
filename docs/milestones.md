# Timo 实施里程碑

本文将个人研发运维助理拆成可逐段验证的实施任务。T3 Code 管线程、原生运行时接入、多仓工作目录与 worktree；Timo 管任务约定、全树预算与收敛、身份引用、受控动作、验收、通知和重启后的对账。先让用户从总助理交办一件事，再扩大能力，不先建设通用管理平台。

**初始状态：2026-11-26，所有里程碑均未验收。** 本文完成只代表实施计划已写入仓库。静态检查、模拟通过、真实接入和真实试用是不同证据，不能互相替代。下列复选框保留为空，实施者完成相应工作并附证据后再勾选。

关联文档：[项目说明](../README.md)、[架构](architecture.md)、[验收](acceptance.md)、[T3 接入](t3-integration.md)。本文件规定推进顺序和退出条件，不预先锁定技术栈、协议字段或状态枚举；实现选择只需满足当前切片的边界。

## 如何使用本计划

- 每次优先完成一条用户能操作、结果能核对的纵向切片。模拟器与真实适配器使用同一条任务路径，不另造仅用于演示的完成流程。
- 每段记录候选版本、T3 与 Provider 版本、执行环境、验收动作、实际观察、证据位置、失败与未测项。凭据值和客户原始敏感数据不得进入提交或报告。
- 本地模拟可以使用临时仓库、受控任务脚本和虚拟平台回执，验证故障分支；真实环境只使用已有授权和可达资源。缺少授权时保留待验项，不以模拟结果宣布真实可用。
- 前一阶段的退出条件不满足时，可以提前开发无依赖的后续切片，但不得宣布后续阶段整体通过。
- 一项任务的费用、期限与执行权限贯穿所有子任务、重试、接力和恢复。验收与必要收尾额度包含在总额内；不得通过换 Runtime 或新建子任务重新获得额度。
- 第一版不要求多 Agent 团队。多个任务可以并行，单任务默认一个负责人；独立检查优先用程序，确有独立工作面时再增加 Agent。

## M0：核实实际 T3 接入边界

**依赖：** 可读取的 T3 源码或发行材料；真实探针还需要实际安装的 T3 服务端、可用 Provider 和对应授权。没有真实环境时，只能完成材料核对与模拟准备。

### 可勾选切片

- [ ] 记录采用的 T3 发行版本、固定提交、服务端运行位置及 Codex、OpenCode 版本，区分上游材料与实际安装能力。
- [ ] 选择一条实际受支持的接入方式，核对创建线程、读取状态、发送消息、中断、恢复、切换执行器的输入、返回和限制；不同时建设多套网关。
- [ ] 核对线程与项目的标识作用域、事件保留与断线缺口、状态补查方式，以及原生会话和附件的可携范围。
- [ ] 核对多仓选择、实际基线解析、worktree 创建与回收、仓外共享文件及缺快照时的恢复行为。
- [ ] 核对权限默认值、受限线程如何创建、工具和业务凭据的实际可达范围。Workflows 仅作可选能力；若启用，单独核对调用者与步骤权限。
- [ ] 核对用量何时可读、是否完整、单轮能否中断、停止后后台进程是否仍运行；列出无法强制执行的预算或停止边界。
- [ ] 建立最小接入模拟器，能返回成功、拒绝、超时、事件缺口和未知执行结果，供后续切片重复使用。

**产物：** [T3 接入记录](t3-integration.md)中的版本与能力表；一个最小适配入口及其模拟器；带实际返回的探针记录。没有的能力写明替代路径或缺口，不把未来接口当现有接口。

### 验收动作与反例

1. 从 Timo 仓库根目录运行仓库提供的只读基线检查：`./scripts/check-t3-baseline.sh ../t3code v0.1.12`。保存它实际检查的材料与结果；这只核对固定版本材料，不证明运行中的服务端支持相关行为。
2. 在已获准的临时环境，通过选定接口创建一个受限线程，发送简单任务、读取结果，再做一次中断与恢复；记录真实线程标识和观察。
3. 用临时双仓目录核对实际解析的基线和工作目录。请求不可用的 Provider 或不存在的恢复对象，确认返回明确失败，没有悄悄换成更高权限或其他执行器。
4. 模拟丢失事件和服务重启后，以状态读取恢复认识；事件流为空不得被解释为任务已完成。

**退出条件：** 最小接入路径有真实探针证据；已明确后续所需能力的支持、限制与替代路径。接力所需的完整故障验证留到 M3。仅有文档、脚本成功或模拟器时，M0 仍未整体通过。

## M1：从总助理交办到单任务交付

**依赖：** M0 的最小接入路径与能力边界。核心任务行为可先用模拟器开发，但本阶段退出还需实际运行时的最薄贯通。

### 可勾选切片

- [ ] 提供一个可用的总助理入口。纯咨询直接回答；承诺交付、后台等待或产生外部动作时建立 Task，并能从同一入口查进度、纠偏和停止。
- [ ] 持久保存原始要求、必须项、可选项、不做项、成功证据、允许动作、费用与期限；区分需求版本、授权版本和执行代次。
- [ ] 为一项任务关联一个 T3 执行线程，由 Timo 的唯一业务任务写入口更新进展；执行者自报完成只作为观察。
- [ ] 建立最小结果检查：针对固定输入生成候选，由独立检查程序核对必须项，再由任务服务接纳并汇报；失败和未知保持可见。
- [ ] 记录全树累计消耗与在途预留，限制自己准入的轮次、并发和动作。用模拟子任务验证额度共享；换执行器、重试与恢复不重置总额。
- [ ] 区分活跃执行、外部等待、等待人、基础设施阻塞与推理停滞。下一次探索须说明要取得什么新证据；保留最佳候选，并在总额内预留验收与必要收尾。
- [ ] 汇总待决问题与通知，只在需要人判断或有重要进展时提醒；普通回复和心跳不重新唤醒主助理。

**产物：** 可操作的总助理入口；单任务记录与执行关联；最小检查程序；预算及进展记录；本地模拟和真实最薄任务的验收证据。不以完成数据库或接口清单代替用户流程。

### 验收动作与反例

1. 用户从总助理交办“检查这份测试日志，给出断连证据，不修改外部系统”。系统登记任务、调用执行者、提交带来源的候选、检查后汇报；用户无需手工建立线程或搬运上下文。
2. 提供没有断连证据的日志，检查程序不得因为执行者写了“已经定位”而接纳。没有发现故障也是允许的结果，但必须与证据和约定相符。
3. 模拟连续相同失败：先验证有限恢复，再触发换方法、具体求助或停止；不能靠增加描述长度延长任务。模拟长作业等待，确认没有持续模型调用来轮询。
4. 将总额度分给两个模拟子任务，并注入重试、在途结果和额度耗尽。确认已分配的额度不会被重复使用，停止接纳新工作后仍能在预留范围内保存证据和释放资源。
5. 在执行中将要求改为“只给已有证据，停止继续调查”，验证新动作按更新后的要求处理，旧结果保留出处而不自动覆盖当前结论。

**退出条件：** 真实用户入口完成一项受限、可独立检查的任务；上述反例可重复。若 Runtime 只能事后报告费用，明确标注在途超额与未知用量，不能宣称精确金额硬封顶。

## M2：多仓、受控外部动作与基本验收

**依赖：** M1 已贯通；M0 的多仓与权限边界已确认；本地模拟平台可用。真实 MR／CI 操作还依赖对应平台授权、账号与网络。

### 可勾选切片

- [ ] 从任务关联资源中选取前后端两仓，保存每仓实际 base SHA、候选 SHA 或不可变制品及工作目录归属；同仓另一任务使用独立 worktree。
- [ ] 接入一种只读诊断身份，记录账号、地域、环境、资源与身份引用；校验目标，按允许数据范围向模型提供日志。
- [ ] 建立受控动作入口，执行前校验任务、执行者、实际身份、目标、参数与当前授权。保留意图和稳定操作 ID，每次尝试另有标识。
- [ ] 通过现有平台工具创建或更新两个 MR，记录平台 ID 与各自 head；在内部 Aone 场景优先使用 `a1` 支持的流程。
- [ ] 按原 CI 标识、候选 head 和平台状态跟踪结果，使用事件或有上限的程序轮询；重试不重新创建已成功的 MR。
- [ ] 为“两仓组合修复 SSE 断连”建立独立检查，从冻结候选和受控检查代码取证，核对约定的漏事件、重复事件和恢复行为。
- [ ] 各必须项独立记录通过、失败或未知。只有候选组合匹配且必须证据齐备才接纳；生产发布另有授权，本切片禁止发布。

**产物：** 多仓任务路径；一种诊断身份接入；MR／CI 适配与操作回执；组合行为检查及证据；权限拒绝与部分成功记录。

### 验收动作与反例

1. 先在本地双仓与模拟平台交办“定位 SSE 断连，必要时修前后端，提两个 MR，等 CI，不要发布”，从总助理一路完成。
2. 在隔离的测试环境制造可重复断连，验证真实诊断只能读取获准日志；账号不符、权限过期和网络不通分别返回可解释原因，不自动换高权限身份。
3. 第一个 MR 成功、第二个明确失败时，保留第一份回执，只处理第二项。第一仓 CI 绿、第二仓仍排队时，任务保持等待，不重新运行已完成部分。
4. 注入“两份单仓 CI 都绿，但组合测试丢事件”以及“CI 针对旧 head”两类反例，均不能宣告整体完成。
5. 执行者尝试发布、调用其他环境身份或绕开受控入口。验证实际平台权限或执行隔离阻止越界；只有界面拒绝、提示词约束不算通过。
6. 检查仓外共享文件、未跟踪文件和另一个任务的 worktree，确认本任务不会覆盖它们；隔离目录不代表共享数据库或凭据已隔离。

**退出条件：** 本地模拟全链及故障反例通过；在获准的真实环境完成诊断、两仓候选、两个 MR 和对应 CI／组合验证。若真实平台尚不可用，只记录模拟通过，M2 保持待真实验收。

## M3：安全接力、重启与未知结果对账

**依赖：** M2 的候选、操作和证据记录；M0 确认的 Codex、OpenCode 能力；可控的断线与进程停止测试环境。

### 可勾选切片

- [ ] 在同一 AppThread 中提供 Codex → OpenCode 接力，携带任务约定、权限、每仓候选、未跟踪文件、已验证事实、失败尝试、外部操作 ID 与剩余额度。
- [ ] 在可交接边界停止旧写者并核对后台进程；旧执行状态未知时保留目录，只允许新执行者读取冻结材料，未确认停止或强制隔离前不得开放写入。
- [ ] 由可信入口分配新执行代次，拒绝旧代次的新动作。已发生动作的迟到回执仍可用于对账，但不能自动恢复旧权限或宣布当前任务通过。
- [ ] 重启后读取持久任务、T3 状态和外部平台状态，重新建立等待与通知；不将内存事件流作为唯一事实来源。
- [ ] 处理“已执行但回执丢失”：保留原操作身份，优先查询；只有确认未执行，或仍可使用下游有效幂等保证时，才按当前授权重试。
- [ ] 在动作准入处检查最新授权；长时间排队后执行须重新核对。需求改口、授权变化与执行权移交分别记录，不能混为一个版本号。
- [ ] 对无法确认的外部效果显示未知、风险和下一核对条件；重复事件不重复执行，也不反复通知同一已确认结论。

**产物：** 接力和恢复路径；操作对账记录；写者状态及授权拒绝证据；重复、乱序、迟到事件与崩溃点的验证记录。

### 验收动作与反例

1. Codex 完成后端修改后，由用户要求改用 OpenCode。新执行者读取未提交及未跟踪工作，继续前端与原 CI；不要求用户重述“不要发布”。
2. 保留一个仍写文件的旧后台进程再发起接力。系统必须阻止新写者进入同一可写目录，而非仅在界面将旧线程显示为停止。
3. 先分别执行[验收剧本](acceptance.md)中的 S02 交接、S03 改口和 S04 丢回执，再组合验证。在平台接受第一个 MR 后、客户端保存回执前断线，第二个 MR 此时尚未准入。用户改为“仅保留已有 MR”，随后换执行器并重启。恢复后查明第一项，拒绝第二项的新建请求。再测改口时第二项已经发出的分支，查询并汇报其实际效果；证据不足则保留未知，关闭已建 MR 需要相应授权。
4. 模拟平台既不能确认成功也不能确认未执行，且不支持有效去重。系统保留未知并停止相关重试，不能据超时推断失败。
5. 在 CI 等待中关闭 Timo，恢复后丢失一段事件、重复投递已有事件，并送达旧执行代次的“完成”消息。状态通过补查恢复，原 CI 继续跟踪，当前验收不被旧消息覆盖。
6. 对比接力、重试和重启前后的总消耗与在途额度，确认未重置；已提交且无法撤回的副作用如实记录，不宣称改口能撤销历史。

**退出条件：** 本地故障注入和获准真实接力均有证据；关键未知分支不会重复写或误报成功。无法停止的旧写者、不可携附件和无法确认的操作都有可见处理路径，不以“上下文已复制”代替安全接力。

## M4：首个可用版本的真实试用与度量

**依赖：** M1—M3 退出条件通过；用户同意的真实试用任务、身份、仓库与平台；试用候选及验收条件已固定。该阶段验证个人产品价值，不新增通用调度或权限平台作为前置。

### 可勾选切片

- [ ] 从总助理交办并完成一项真实 SSE 双仓任务：只读诊断、必要修改、两个 MR、等待对应 CI、组合验证、明确不发布。
- [ ] 同一任务包含一次用户发起的 Codex → OpenCode 接力，并展示原约定、候选、操作与预算的延续。
- [ ] 在专用测试资源上执行回执丢失、改口、重启、旧写者和重复事件反例；破坏性注入不进入未经授权的真实业务资源。
- [ ] 用户可随时从总助理得到当前目标、最近有效证据、等待原因、下一动作和真正需要自己决定的事项；离线数据标明最后核验时间。
- [ ] 由独立检查读取候选、平台回执与行为证据，复核作者错误自报完成、旧 CI、两仓组合失败和部分成功均未被误收。
- [ ] 记录人工对照及 Timo 试用的正确交付、完成时间、主动查状态次数、重复解释次数、审阅与返工分钟数、全部尝试成本和缺失用量。
- [ ] 整理试用缺陷，区分阻塞交付、影响效率与可选体验改进；修复后复验受影响情形，不用增加 Agent 数量掩盖同一故障。

**产物：** 首版试用记录、精确候选和可回读证据；用户操作与收益对照；已知限制；下一阶段仅针对实际缺口的任务列表。

### 验收动作与反例

1. 用户从总助理发起，不手动搬运执行上下文。最终核对两份 MR、精确 head、有效 CI、SSE 行为证据和未发布状态；缺少任一必须证据均不能宣布整体通过。
2. 用户问“现在需要我做什么”，只能得到当前确实需要人的决定及其依据；已授权的账号选择、查 CI 与继续执行不能反复交回人处理。
3. 用户在一项任务等待 CI 时交办另一项独立任务，验证资源归属和额度不会串用；任务共享数据库或发布目标时按资源约束排队。
4. 与用户原有手工切终端的同类流程对照，分别报告正确性、时效、人工时间和成本。失败、取消、超时计入尝试；零正确交付时“每项正确交付成本”无定义。
5. 单任务多 Agent 并非本阶段必选。需要评估时，再对相同任务、环境、权限、标准和总预算比较单执行者、单执行者并发工具、小组分工；不同策略均走相同验收。

**退出条件：** 真实主路径与受控反例通过，用户确认可以在标注的范围内日常使用；证据和未解决限制可回读。若只有演示、模拟或未经核对的作者结论，仍不能称首个可用版本。试用样本有限时只报告样本观察，不宣称普遍提效、生产发布就绪或无人值守可靠。

## 后续拓展：由已验证需求触发

**依赖：** M4 的真实使用证据；每项拓展单独明确授权、验收与退出条件，不打包成首版前置。
